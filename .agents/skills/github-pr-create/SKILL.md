# GitHub PR 생성

사용자가 명시적으로 요청한 경우에만 PR을 생성한다. 저장소에 기존 PR 규칙이 있으면 이를 따른다.

PR 생성 전:

- 현재 브랜치, 저장소 상태, 리모트, 대상 베이스 브랜치 대비 diff를 확인한다.
- 브랜치에 커밋된 변경이 있고 푸시되었거나 푸시 가능한지 확인한다. 사용자의 명시적 승인 없이 관련 없는 미커밋 변경을 포함하지 않는다.
- 최종 변경에 대해 아직 실행하지 않았다면 관련 프로젝트 검증을 실행한다. 실패가 있으면 정상 PR처럼 보이게 생성하지 말고 실패를 보고한다.

PR 본문을 작성하기 전에 다음 중 하나의 템플릿을 선택해 읽는다.

- `react-component-generator`에서는 [한국어 템플릿](references/pr-body-template.ko.md)을 사용한다.
- 그 외 오픈소스 저장소에서는 [영문 템플릿](references/pr-body-template.en.md)을 사용한다.

실제로 변경한 내용과 실행한 명령어만 채우고, 해당하지 않는 섹션은 제거한다. 실행하지 않은 테스트·배포·리뷰를 했다고 작성하지 않는다.

검증된 베이스 브랜치와 간결하고 설명적인 제목으로 PR을 생성한다. GitHub가 해당 브랜치의 적절한 기존 PR을 반환하면 중복 생성하지 말고 URL을 반환한다. 생성 또는 푸시에 실패하면 오류를 보고하고 멈춘다. 원인을 해결하지 않은 채 외부 변경 작업을 재시도하지 않는다.

생성 후 결과 URL을 검증해 보고한다. 지원되는 환경이라면 생성한 PR을 현재 작업에 연결한다.

## 서브에이전트 사용

PR 생성은 **항상 전담 서브에이전트**가 수행한다.

- 조율 에이전트는 PR 생성 요청을 받으면 서브에이전트를 생성하고, 저장소 경로·대상 브랜치·사용자의 명시적 PR 생성 승인·이미 실행한 검증 결과를 전달한다. 조율 에이전트는 직접 푸시하거나 PR을 생성하지 않는다.
- 전담 서브에이전트는 이 스킬의 검사·템플릿 선택·푸시·PR 생성 과정을 직접 수행하며, 다시 다른 서브에이전트에게 위임하지 않는다.
- 서브에이전트를 생성할 수 없으면 PR을 만들지 말고 그 제약을 보고한다.
- 서브에이전트도 같은 권한 경계를 따른다. PR 자료는 자유롭게 준비할 수 있지만, 사용자가 해당 변경을 명시적으로 승인한 경우에만 PR 생성 또는 푸시를 수행한다.
